# SPEC P_CLAIMS: NEW `pieces/p1_claims.py` + NEW `pieces/test_p1_claims.py` (safe parallel loops: shared key ledger, dead-key markers, file claims held by the job process, job launcher)

GOAL (owner decision P1-D6, 2026-10-29, option 1 after 10 design reviews): several fix-loop processes may run at the same time (cap 4, up to 8 for independent jobs) and use all 14 NVIDIA keys safely. The module supplies (1) a cross-process key ledger with a drop-in pool class, (2) file claims so two jobs never touch the same file, (3) a launcher that takes the claims and then runs the unchanged loop script inside the SAME process. The module makes NO network call and NO model call. Keys are never written anywhere: only `sha256(key)[:16]` hashes.

REAL FACTS (verified in this repo):
- The loop builds its pool with `KeyPool(keys)` from `scripts/image_trials/nvidia_trial.py`. Interface to imitate: attribute `keys` (list of key strings), `acquire() -> (index, key)` which blocks (sleeps) until a key is ready, `report(index, status)` where `status` is the HTTP status (0 means the request failed with an exception or timeout), property `live` (number of keys not retired). The original class raises `AllKeysUnavailable(RuntimeError)` when every key is retired. Statuses 401, 402 and 403 mean the key is invalid or out of credit (retire it). The original keeps 10 requests per key per rolling 60 s (owner safety margin; the real provider limit is 20) and cools a key for 60 s after any failure.
- The 14 keys belong to 14 different accounts, so limits are per key.
- The loop is started as `python scripts/source/fix_loop.py --job <job.json> --root <repo>`. A job JSON has `name`, `spec`, `files` (list), `tests` (list), `reference` (list). The loop script must stay UNCHANGED; the launcher runs it with `runpy.run_path(<repo>/scripts/source/fix_loop.py, run_name="__main__")` after setting `sys.argv`, and the loop ends with `SystemExit`.
- Windows 11, Python 3.14. On Windows use `msvcrt.locking`; elsewhere use `fcntl.flock` (so tests also run on Linux). The lock modes needed: non-blocking exclusive lock of byte 0, and unlock.
- Every key choice must PERSIST its request stamp BEFORE the request is sent, so a persistently unwritable disk blocks all sending.

FUNCTIONS AND CLASSES (public):
1. `key_hash(key: str) -> str`: `hashlib.sha256(key.encode()).hexdigest()[:16]`.
2. `canonical_path(path) -> str`: `os.path.normcase(os.path.realpath(os.path.abspath(str(path))))`; used for every claim, including the job file path.
3. `class LedgerError(RuntimeError)`, `class LedgerLockTimeout(LedgerError)`, `class AllKeysUnavailable(RuntimeError)`, `class ClaimConflict(RuntimeError)` (message names the conflicting canonical path).
4. `class FileLock`: persistent lock file (opened once, never deleted, created if missing); `acquire(timeout_s=30.0, poll_s=0.05)` retries a non-blocking lock until the timeout, then raises `LedgerLockTimeout`; `release()`; usable as a context manager. The OS drops the lock if the process dies. No stale-lock cleanup exists or is needed.
5. `class KeyLedger(directory, per_key=10, window_s=60.0, cool_s=60.0, dead_cool_s=86400.0, offset=0, clock=time.time, write_json=None, make_marker=None, exit_fn=os._exit)`: files in `directory` (an existing folder, never created): `key_ledger.json` = `{"version":1,"keys":{hash:{"stamps":[floats],"cool_until":float}}}`, `key_ledger.lock` (the lock file), and one `dead_<hash>.mark` per dead key. `write_json(path, obj)` and `make_marker(path)` default to real implementations (write via temp file in the same folder then `os.replace`; marker via `os.open(path, O_CREAT|O_EXCL|O_WRONLY)` where an existing marker counts as success) and are injectable for tests.
   - `choose(hashes) -> int | float`: ONE locked transaction. Read the ledger (missing = empty; unparseable = rebuild with every key cooled for `cool_s` from now and no stamps) and list the `dead_*.mark` files (a failed listing raises `LedgerError`; refuse to send). Prune stamps older than `window_s`. A key is a candidate when it has no marker, `cool_until <= now` and fewer than `per_key` stamps. Order candidates by fewest stamps, ties broken by rotation starting at `offset % len(hashes)`, so different loops start on different keys. If a candidate exists: append `now` to its stamps, WRITE the ledger (failure raises `LedgerError`), release the lock, return its index. If no candidate: when every key has a marker raise `AllKeysUnavailable`; otherwise return the number of seconds to wait (a float, at least 0.05): the smallest of `cool_until - now` and `oldest stamp + window_s - now` over live keys. The lock is always released before the caller sleeps.
   - `report(key_hash, status)`: success (200 to 299) changes nothing. A dead status (401, 402, 403) is handled WHILE HOLDING the lock with two INDEPENDENT attempts: (A) set `cool_until = now + dead_cool_s` in the ledger and write it; (B) create the marker file. If both fail, keep the lock, call `exit_fn(2)` (real behaviour: the process ends and Windows frees the lock). If exactly one fails, release the lock and raise `LedgerError` (the process poisons itself). Any other status (not 2xx, including 0, 404, 429, 500) sets `cool_until = max(existing, now + cool_s)` and writes the ledger (failure raises `LedgerError`).
6. `class LedgerKeyPool(keys, directory, offset=None, per_key=10, clock=time.time, sleep=time.sleep, **ledger_options)`: duck-compatible with the original pool: `keys` (copy of the list), `acquire() -> (index, key)` loops over `KeyLedger.choose` sleeping when it returns a wait, `report(index, status)` calls `KeyLedger.report`, property `live` (keys without a marker; counts markers on every call). `offset` defaults to `os.getpid() % len(keys)`. It keeps an in-process dead set; once ANY `LedgerError` has been raised the pool is poisoned: every later `acquire` raises `LedgerError("poisoned")`. The pool never stores or prints a key; only `key_hash` values are passed to the ledger.
7. `class ClaimStore(directory)` and `class Claim`: `claim(paths, job_name) -> Claim` canonicalises every path, creates or opens `claim_<sha256(canonical)[:16]>.json` in `directory` (information only: path, job, pid, started) and takes a non-blocking `FileLock` on it. Claims are ALL-OR-NOTHING: on the first conflict release every lock taken so far and raise `ClaimConflict`. A path is claimed when the lock attempt fails and free when it succeeds (old file content is ignored). `Claim.release()` and context-manager exit release all locks. The OS drops the locks if the holder dies, so PID reuse and stale claims cannot occur.
8. `run_job(job_path, repo, claims_dir=None, loop_script=None, environ=None) -> int`: read the job JSON; claim `canonical(job file)` plus every entry of `files` and `tests` (relative to `repo`) in `claims_dir` (default: `<repo>/_loop`); set `PYTEST_ADDOPTS` to include `-p no:cacheprovider` (append to an existing value without duplicating), set `P1_LEDGER=1` and `P1_KEY_OFFSET` to `os.getpid() % 14` in `environ` (default `os.environ`); set `sys.argv = [loop_script, "--job", str(job_path), "--root", str(repo)]`; run the loop script with `runpy.run_path(loop_script, run_name="__main__")` inside the SAME process; convert `SystemExit(code)` to the returned int (None means 0); ALWAYS release the claims in a `finally`. `loop_script` defaults to `<repo>/scripts/source/fix_loop.py`. A conflict raises `ClaimConflict` before the loop script runs.
9. `main(argv) -> int`: `python pieces/p1_claims.py run <job.json> [repo]`; repo defaults to the current directory; prints one line `claims: conflict <path>` and returns 3 on `ClaimConflict`, otherwise returns the loop's code. Guard with `if __name__ == "__main__": raise SystemExit(main(sys.argv[1:]))`.

DECISION P1-D10 (binding; rounds 0-1 failed on gaps in this spec, found by running the tests): (a) ORDER OF CHECKS in `LedgerKeyPool.acquire`: the poisoned check comes FIRST (a poisoned pool raises `LedgerError("poisoned")` before anything else, even when every key is dead); only then the ledger. (b) A corrupt or unparseable ledger is rebuilt AND WRITTEN back to disk inside the same locked transaction, also when the call then returns a wait; the next call must find a valid ledger with the cooldowns in it, so after the fake clock passes `cool_s` the next `choose` returns an int index. (c) LOCK BYTE: every byte-range lock (ledger lock file and claim files) is taken on the single byte at OFFSET 1073741824 (2**30), far beyond the end of any content, never on a byte that holds content; Windows blocks other handles from reading or writing a locked range, so locking byte 0 of a file whose content is written breaks. Claim info content is written ONLY after the lock is held, and never when the lock attempt failed. (d) Any `OSError` (PermissionError, EACCES, EAGAIN, EDEADLK) raised by the lock attempt, or by opening a claim file that another handle holds, means CLAIMED and becomes `ClaimConflict` (after releasing locks already taken in that call); a claim of the same canonical path made twice in ONE process by two different spellings must also raise `ClaimConflict`. (e) CROSS-PROCESS CONTRACT of `choose` and `report`: the whole read-merge-write happens while the lock is held (read inside the lock, never before); the ledger is written to a temp file named `key_ledger.json.<pid>.tmp` (per process) and then `os.replace`d; stamps of keys the call did not touch are carried over unchanged; the multiprocessing test must therefore see exactly 45 stamps. (f) AFTER `exit_fn(2)` returns (only possible with a test fake) `report` raises `LedgerError("both writes failed")`; the test uses a fake `exit_fn` that records its argument and wraps the call in `pytest.raises(LedgerError)`. (g) A status reported for an unknown key hash is ignored.

DECISION P1-D19 (AS BUILT; this block overrides any earlier line that disagrees): (1) `main` returns 4 on a claim conflict (the loop uses 3 for escalate) and 2 on bad usage. (2) `KeyLedger.report` on a corrupt ledger does NOT rewrite it (a one-key rewrite would clear the other keys' cooldowns): it only writes the dead marker for 401/402/403 and returns; the next `choose` rebuilds the ledger with every key cooled and writes it back. (3) `run_job` refuses (ValueError) a job whose `fixers` is missing or not exclusively `nemotron`; it also claims `<repo>/_loop/<job name>` besides the job file, `files` and `tests`; duplicate canonical paths inside ONE `claim()` call count once (a job lists its test under both files and tests), while a second call on the same canonical path conflicts. (4) `FileLock.acquire` turns an `OSError` from opening the lock file into `LedgerError`; `ClaimStore` turns it into a conflict. (5) A forced stop, a crash or Ctrl+C skips the loop's restore step: wipe `_loop/<job>` and the job's piece files before relaunching. (6) WIRING (P1-D20): `scripts/image_trials/nvidia_trial.py` exposes `KeyPool(keys, ...)` as a factory; with env `P1_LEDGER=1` (set by the launcher) it returns a `LedgerKeyPool` subclass that raises the loop's own `AllKeysUnavailable`, using `P1_LEDGER_DIR` (default `<repo>/_loop`) and `P1_KEY_OFFSET`; otherwise it returns the in-process pool. Only transient failures switch keys in `chat_stream` (401/402/403, 429, 5xx, status 0 without a finish value).
